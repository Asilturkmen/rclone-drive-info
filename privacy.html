Privacy Policy

Effective date: 25 October 2026

This policy explains how Rclone-Drive accesses, uses, stores, and shares Google user data. It describes the actual setup, which is small: one person using the open-source program Rclone on their own computers to work with their own Google Drive.

1. What this policy covers

Rclone-Drive is the name of a Google Cloud project and its Google OAuth 2.0 client. The client is used only by my own installations of Rclone on Windows and macOS computers, so that Rclone can access my personal Google Drive. It is a personal, single-user configuration. It is not a commercial service, it is not offered to other people, and it is not a standalone cloud storage application.

This policy covers:

  • Google user data that Rclone accesses through the Rclone-Drive OAuth client; and
  • this informational website (the Rclone-Drive homepage and this Privacy Policy page).

Rclone itself is an independent open-source project and is not developed, endorsed, or maintained by me or by Google. Its behaviour is documented at rclone.org.

2. How the setup works

  1. Rclone runs locally on my computer.
  2. When a Google Drive remote is configured, Rclone opens Google's sign-in and consent page in the web browser. Google handles the sign-in. Rclone never sees the Google Account password.
  3. After consent, Google sends an authorization code to a temporary local address on the same computer (Rclone listens on 127.0.0.1 during setup). Rclone exchanges the code with Google for an access token and a refresh token.
  4. Rclone then calls the Google Drive API directly from the computer over HTTPS to list, transfer, and manage files.

There is no server, backend, database, or account system operated for Rclone-Drive. Requests go from Rclone on my computer straight to Google's APIs and do not pass through any system run by me or through this website.

3. Google permissions requested

The Rclone-Drive OAuth client is configured with the following Google OAuth scopes:

Scope What it allows
https://www.googleapis.com/auth/drive See, edit, create, and delete all files in the user's Google Drive.
https://www.googleapis.com/auth/docs Google Docs access. Rclone's documentation lists this scope for a self-created client. Together with the Drive scope it covers viewing, creating, editing, and deleting Google Docs editor files (Docs, Sheets, Slides, and similar) stored in Drive.

Google's consent screen shows the permissions being granted at the time of authorization, and that screen is the authoritative list. These permissions are broad. They allow Rclone to read, create, modify, and delete Google Drive files. They are requested because Rclone is used as a full file manager and synchronisation tool for my Drive, as described in Rclone's Google Drive documentation. The exact scope Rclone asks for at sign-in is set in its local configuration and can be narrowed (for example to read-only access), in which case Google's consent screen shows the reduced permission.

4. Google user data accessed and how it is used

Depending on the command being run, Rclone may access:

  • file and folder names, sizes, modification times, checksums, MIME types, and similar metadata;
  • file contents, when files are downloaded, uploaded, copied, or synchronised;
  • Google Docs, Sheets, Slides, and other Docs editor files, which Rclone can export to standard formats such as .docx or .xlsx when downloading;
  • information about shared drives and trash, when those features are used.

This data is used only to carry out the file operations I run in Rclone: listing, downloading, uploading, copying, synchronising, moving, renaming, deleting, and mounting my Google Drive files on my own computers. It is not used for any other purpose. It is not used for advertising, profiling, analytics, or to develop, improve, or train generalised artificial intelligence or machine learning models.

5. Where data and credentials are stored

OAuth credentials and tokens

The OAuth client ID, client secret, access token, and refresh token are stored by Rclone in its local configuration file, rclone.conf, on each of my computers. By default this file is located at:

  • Windows: %APPDATA%\rclone\rclone.conf
  • macOS: ~/.config/rclone/rclone.conf

These credentials are never sent to, collected by, or stored on this website, and they are not published in the website's repository. Rclone offers optional encryption of its configuration file with a password; whether it is used is a local choice and is not something this website controls.

Google Drive files

Files downloaded or synchronised with Rclone are stored on my own computers, in the locations I choose. When Google Drive is mounted with caching enabled, Rclone may also keep temporary copies of file data and directory listings in a local cache folder on the same computer. No copies are kept anywhere else as part of this setup.

Retention

Local files and caches remain on my computers until I delete them or Rclone clears its cache. Tokens remain in rclone.conf until the remote is removed, the file is deleted, or access is revoked (see section 9).

6. Sharing and transfer

Google user data obtained through Rclone-Drive is not sold, rented, or shared with anyone. It is not transferred to third parties, advertising platforms, data brokers, or information resellers. No person other than me, the account owner, reads the data.

The only parties involved in processing are Google, which hosts the Drive files and provides the APIs, and my own computers running Rclone.

7. Google API Services User Data Policy

Rclone-Drive's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is used only to provide the file-management functionality described in this policy.

8. This website

This website consists of two static pages hosted on GitHub Pages. It exists only to describe Rclone-Drive and publish this policy. It:

  • has no backend, database, account registration, sign-in, or authentication form;
  • does not perform any OAuth flow and does not call Google APIs;
  • does not receive, collect, store, or transfer Google Drive files or any other Google user data;
  • contains no JavaScript, analytics, advertising, tracking pixels, or third-party embeds, and sets no cookies.

Like any website, the hosting provider processes ordinary technical information needed to deliver the pages, such as the visitor's IP address, browser user agent, and the requested URL. This is handled by GitHub under the GitHub General Privacy Statement. I do not have access to individual visitor logs from GitHub Pages.

9. Revoking access and deleting data

  • Revoke Google access: open the Google Account's Third-party apps & services page, select Rclone-Drive, and remove its access. After this, the stored refresh token stops working and Rclone can no longer access Google Drive until it is authorized again.
  • Remove local credentials: run rclone config delete <remote-name>, or delete the relevant section of rclone.conf, to remove the stored tokens from a computer.
  • Remove local copies: delete downloaded files and Rclone's cache folder on the computer.

Revoking access does not delete any files in Google Drive. Files in Drive are managed through Google Drive itself.

10. Changes to this policy

If the way Rclone-Drive accesses or uses Google user data changes, this page will be updated before the change takes effect and the effective date above will be revised. The history of this page is public in the site's repository.
